# Codex Automation

Project baseline: follow [`docs/project-specs.md`](project-specs.md) and [`AGENTS.md`](../AGENTS.md). Automation must not store secrets or private student/customer data.

## Stop Hook

At the end of a Codex prompt, the Stop hook runs the local automation pipeline:

1. Stage all current repository changes.
2. Ask `codex exec` to summarize the staged diff.
3. Update `changelog.md` with plain human-readable entries.
4. Generate a Conventional Commit message.
5. Stage the changelog update.
6. Commit all staged changes.
7. Push to the configured upstream when available.

The hook is implemented by:

- `.codex/hooks/auto-commit-push.sh`
- `.codex/hooks/generate_commit_artifacts.py`

## Changelog Rules

`changelog.md` is generated in simple human English.

Entries must avoid:

- programming code
- class, method, namespace, or file names
- raw URLs
- markdown links
- package names and internal automation details unless the change is only automation

The goal is for a project owner or driving-school operator to understand what changed without reading code.

## Commit Message Rules

Commit messages are generated by `codex exec` from the staged diff and must follow Conventional Commits.

Examples:

```text
feat(students): add enrollment group workflow
docs: update local Orchid workflow
fix(crm): preserve lead source during conversion
```

The automation validates the first line and falls back to a safe maintenance message if generation fails.

## Disable Or Debug

Disable the auto commit/push hook for one run:

```bash
CODEX_AUTO_PUSH_DISABLED=1 bash .codex/hooks/auto-commit-push.sh
```

Run only changelog and commit-message artifact generation without AI:

```bash
git add -A
python3 .codex/hooks/generate_commit_artifacts.py --no-ai
```

Hook logs are written under Git's internal metadata directory as `codex-auto-push.log`.
